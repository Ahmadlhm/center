# إدارة المراكز القرآنية

منصة عربية متعددة المراكز للمديرين والمعلّمين. يضم وضع التجربة مركز نداء الخير القرآني وتقسيمته، مع بيانات نموذجية. ينشئ مدير المنصة المراكز أو يقبل طلبات انضمامها، ويضبط الهيكل والقوانين من لوحة إدارة المنصة.

## التشغيل باستخدام Docker

من مجلد المشروع:

```sh
docker compose up -d --build
docker compose ps
```

افتح [المنصة المحلية](http://localhost:8088). اختر **مدير المركز** أو **معلّم** أو **إدارة المنصة** من قائمة التجربة في صفحة الدخول. تعمل الإعدادات الافتراضية على عنوان الجهاز المحلي. على Windows مع Docker داخل WSL، نفّذ `wsl -u root -e docker compose up -d --build` من مجلد المشروع.

| الحاوية | وظيفتها |
| --- | --- |
| `web` | تطبيق React وTypeScript العربي. وهي نقطة الدخول المنشورة. |
| `gateway` | توجيه API إلى الخدمة المعنية. |
| `identity` | طلبات الانضمام، الدعوات، الأدوار، الجلسات، ومفاتيح المرور. |
| `people` | الوحدات والشعب والطلاب والفترات والانتساب وقواعد المركز. |
| `education` | اللقاءات والحفظ والمراجعة والدورات والتلاوة والمسابقات والتقارير. |
| `work` | حضور المعلّمين والتكليفات. |
| `documents` | رفع شهادات PDF وPNG وJPEG حتى 10 MB، وربطها بالشعبة والطالب وصلاحيات التنزيل. |
| `import` | استخراج الطلاب من Excel أو من الصور وPDF عبر Tesseract وPoppler. |
| `postgres` | مثيل PostgreSQL واحد مع مخطط وهوية قاعدة بيانات لكل خدمة مالكة للبيانات. |

تتصل الخدمات على شبكة داخلية. يحفظ PostgreSQL بياناته في `postgres-data`. تُحفظ ملفات الشهادات بصيغة `bytea` في `documents.certificates`. يظهر الملف نفسه في **مجلد الشعبة** وتبويب **الشهادات** في ملف الطالب عند الربط به. يستطيع المدير أو معلّم الشعبة ربط شهادة بالشعبة عند الرفع وإسنادها للطالب لاحقًا. معاينة الاستيراد تُرجع الصفوف المستخرجة إلى واجهة المدير، وتُحفظ الصفوف التي يعتمدها فقط.

## إعداد مركز جديد

يستطيع مدير المنصة إنشاء مركز من **إدارة المنصة ← الطلبات والمراكز ← إضافة مركز**، مع إصدار حساب مديره في نفس العملية أو إضافته لاحقًا. يفتح زر **الحسابات** بجانب المركز صفحة إضافة حسابات المدير والمعلّمين. يظهر للحساب الجديد بريد وكلمة مرور مؤقتة، ويظهر لصاحب الحساب الحالي رابط انضمام للمركز.

يمكن لمسؤول المركز أيضًا بدء العملية عبر طلب انضمام.

1. يفتح مسؤول المركز «يريد مركزك الانضمام؟» ويقدّم الطلب.
2. يوافق مسؤول المنصة ويشارك رابط التفعيل مع المدير المقترح. وتُسلَّم روابط تفعيل الموظفين من واجهة المسؤول التي أنشأتها.
3. يضبط مدير المنصة بيانات المركز وخريطته وهيكله وشعبه وخيارات الدوام، ويصدر حسابات الموظفين. يدير مدير المركز الطلاب ورصد الدوام ومراجعة الطلبات.
4. يضيف الموظف مفتاح مرور من حسابه. خلال نافذة الدوام يفتح «دوام الموظفين» ويضغط «إثبات الحضور». يمكن للمعلّم إثبات حضور اللقاء من كشفه كذلك. يتحقق الجهاز محليًا بالبصمة أو رمز قفله، ويتحقق الخادم من التوقيع والزمن والموقع.

## إعداد بيئة فعلية

بعد اعتماد إصدار على `main`، استخدم Docker Engine مع إضافة Docker Compose على خادم الإنتاج. وجّه سجل DNS من النوع `A` لاسم النطاق إلى عنوان الخادم، وافتح المنفذين `80` و`443`. يُصدر Caddy شهادة HTTPS ويجددها. [متطلبات HTTPS من Caddy](https://caddyserver.com/docs/automatic-https)

انسخ `.env.production.example` إلى `.env` في مجلد الإنتاج، واضبط صلاحية الملف على `600`. اكتب اسم النطاق في `CENTER_DOMAIN` دون بروتوكول أو مسار. ولّد قيمة مستقلة لكل مفتاح وكلمة مرور لقاعدة البيانات، مثل استخدام `openssl rand -hex 32` لكل قيمة. عيّن بريد وكلمة مرور مدير المنصة الأول، ثم غيّر كلمة مروره وسجّل مفتاح المرور عند أول دخول.

```sh
docker compose -f compose.yaml -f compose.production.yaml config --quiet
COMPOSE_PARALLEL_LIMIT=2 docker compose -f compose.yaml -f compose.production.yaml build
docker compose -f compose.yaml -f compose.production.yaml up -d --no-build
docker compose -f compose.yaml -f compose.production.yaml ps
```

تُنشأ بيئة الإنتاج في مشروع Compose مستقل باسم `quran-center-production`. ينشر Caddy منفذي HTTP وHTTPS فقط، وتبقى PostgreSQL وخدمات التطبيق على شبكات Docker. يعطّل إعداد الإنتاج بيانات التجربة ويُلزم اتصال المستخدمين بـ HTTPS.

تُنشأ أدوار قاعدة البيانات عند تهيئة التخزين لأول مرة. عند تغيير كلمات المرور لقاعدة موجودة حدّث الأدوار فيها بالتزامن مع الإعدادات. اضبط موقع المركز وحدود الدقة والنافذة الزمنية بعد تجربتها على هواتف المعلّمين داخل المبنى. يستعمل إثبات الدوام الموقع المبلّغ من جهاز المستخدم وتحقق مفتاح المرور. تظهر طلبات المراجعة للمدير عند تعذّر التحقق.

### تحقق مدير المنصة بتطبيق Google Authenticator

يدخل مدير المنصة بالبريد وكلمة المرور. عند أول دخول، امسح رمز QR من تطبيق Google Authenticator ثم أدخل الرمز المكوّن من ستة أرقام واحفظ رموز الاسترداد. يولّد التطبيق رمزًا جديدًا كل ٣٠ ثانية، ويمكن استخدام أحد رموز الاسترداد مرة واحدة. [طريقة إعداد Google Authenticator](https://support.google.com/accounts/answer/1066447)

تستخدم المنصة مفاتيح حماية البيانات من وحدة التخزين `identity-keys` لتشفير مفتاح التطبيق في PostgreSQL. احتفظ بنسخة منفصلة ومحمية من هذه الوحدة مع نسخ قاعدة البيانات حتى يعمل التحقق بعد الاستعادة. يبقى التحقق بمفتاح المرور لحساب مدير المركز، وإثبات الدوام يعمل وفق إعدادات المركز.

يمكن أخذ نسخة احتياطية من **جميع المخططات، بما فيها الشهادات** عبر الأمر التالي. احفظ الناتج في تخزين مناسب محمي بالوصول، واختبر الاستعادة في بيئة منفصلة.

```sh
docker compose -f compose.yaml -f compose.production.yaml exec -T postgres pg_dump -U center_dba -d center -Fc > center.dump
```

## الاختبارات وإدارة الإصدارات

```sh
dotnet build server/Center/Center.csproj
cd web
npm ci
npm run build
npx playwright install chromium
node tests/smoke.mjs
```

يستهدف اختبار الدخان بيئة تجربة على `http://localhost:8088` افتراضيًا. يدعم `CENTER_TEST_ORIGIN` عنوانًا مختلفًا و`CENTER_CHROME` مسار Chrome موجودًا. ينشئ سجلات اختبار ومركزًا داخل قاعدة التجربة، ويختبر الأدوار وعزل المراكز والشهادات والتقارير والتكليفات ورصد الحصة ومفتاح مرور افتراضي. تُحفظ لقطات التحقق في `.local`.

لاختبار إضافة مركز وحسابات مديره ومعلّميه من الواجهة، شغّل `node tests/center-provisioning.mjs` على بيئة التجربة.

فرع التطوير لهذا الإصدار هو `version-1.0`. تُدمج الإصدارات المقبولة مع `main` عند اعتمادها للإنتاج.

على خادم Hetzner تفحص `quran-center-deploy.timer` فرع `main` عبر Deploy Key للقراءة فقط كل 25 ثانية تقريبًا. يبدأ النشر بعد تغيير الفرع ويحتفظ بالإصدار السابق لاستعادته عند فشل التحقق. يمكن متابعة آخر نتيجة باستخدام `journalctl -u quran-center-deploy.service -n 30`.

## التطبيقات المحمولة

مجلدا `web/android` و`web/ios` يحتويان مشروعي Capacitor. تستخدم النسخة الداخلية عنوان HTTPS الخاص بالمنصة في `CENTER_APP_URL`، حتى تعمل واجهة الموظف على نفس نطاق الهوية ومفاتيح المرور. الموقع من إضافة Geolocation الأصلية.

- على Android اضبط شهادة التوقيع وانشر محتوى `deploy/mobile/assetlinks.example.json` بعد تعبئته على النطاق في `/.well-known/assetlinks.json`. افتح المشروع في Android Studio بعد `npm run mobile`.
- على iOS اضبط `CENTER_APP_DOMAIN` في إعدادات Xcode على اسم النطاق، وأكمل معرف الفريق والتوقيع. انشر ملف تعريف النطاق من `deploy/mobile/apple-app-site-association.example` في `/.well-known/apple-app-site-association`. يتطلب بناء iOS نظام macOS وXcode.

تسبق تجربة مفاتيح المرور والموقع على هواتف حقيقية وتوقيع الحزم مرحلة توزيع التطبيقات. [متطلبات WebAuthn في Android WebView](https://developer.android.com/reference/androidx/webkit/WebSettingsCompat) · [إعداد مفاتيح المرور في WKWebView](https://developer.apple.com/documentation/authenticationservices/supporting-passkeys/)

## حدود الإصدار الأول

تُقرأ التقارير عند الطلب من مخازن الخدمات المعتمدة. تستخدم سجلات الشعب والتعليم والدوام تجميعًا مستقلًا لكل مركز مع معاملات PostgreSQL، بينما تخزن الشهادات في جدول مفهرس لكل ملف. يناسب ذلك التشغيل الأولي، ويتيح لكل خدمة تغيير تخزينها خلف واجهتها عند زيادة حجم النشاط. قد يحتاج استخراج OCR من كشوف حقيقية ضبط التعرف واختبار الدقة على نماذج المركز. قدّم ملفات Excel مع الأعمدة بالترتيب التالي: رقم الطالب، الاسم، تاريخ الميلاد، هاتف وليّ الأمر. الصف الأول للعناوين.

## خط الواجهة

تستخدم الواجهة خط **Noto Sans Arabic Variable**. تُضمَّن أوزان الخط وترخيصه مع بناء الويب، ويحمّله المتصفح من حاوية الواجهة مباشرة. [ترخيص الخط](web/public/licenses/noto-sans-arabic.txt)

يشمل اختبار `node tests/courses-and-reports.mjs` إخفاء تقارير الإدارة عن المعلّم، وفلاتر الوحدات والشعب، واعتماد إسناد المعلّمين، والإشعارات، ولقاءات التلاوة، وإسناد المسابقات.

## الكتالوج والحسابات

يعدل مدير المنصة أنواع الوحدات ومناهج التلاوة وقوالب فئات المسابقة من لوحة «إدارة المنصة». أسماء السور وعدد آياتها وبدايات الأجزاء والصفحات مرجع ثابت للقراءة فقط، يحمّله الخادم من بيانات مصحف المدينة المضمّنة. تُحفظ مقاطع التسميع على شكل نطاقات آيات عند اختيار سورة أو جزء أو صفحة، وتُحتسب الآية مرة واحدة. بيانات التقسيم مأخوذة من Tanzil Metadata، © 2008–2009 Tanzil Project، CC BY. [مصدر بيانات السور والأجزاء والصفحات](https://tanzil.net/docs/Quran_Metadata)

مناهج التلاوة تبدأ بفصول كتاب «المنير في أحكام التجويد». تحتفظ كل دورة جديدة بنسخة من مقررها. تسجّل الإدارة أو المعلّم المكلّف أجزاء الإجازة التي اختارها الطالب من القائمة المتاحة. فصول الحفظ منفصلة عن عقد اللقاءات النظرية والعملية.

تُحفظ كلمات المرور مجزأة باستخدام ASP.NET Core Identity PasswordHasher. ينتهي الرمز المؤقت خلال ثلاثة أيام ويُلزم النظام بتغييره في أول دخول. لتفعيل إرسال رابط «نسيت كلمة المرور»، اضبط `CENTER_SMTP_HOST` و`CENTER_SMTP_PORT` و`CENTER_SMTP_FROM` ومعلومات المصادقة عند الحاجة. يستخدم الإرسال STARTTLS. يستطيع مدير المنصة إصدار كلمة مؤقتة جديدة أو إبطال مفاتيح المرور من صفحة الحسابات. تُعرض بيانات الدخول عند إصدارها فقط.

لتشغيل اختبار الصلاحيات والمناهج والدوام من مجلد `web` استخدم `node tests/platform-settings.mjs` على بيئة التجربة.
